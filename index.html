RE-FIT

역할 데이터 파이프라인 단독 설계·구축 · 추천 최적화 · 기술 비교 실험

문제

이력서 기반으로 채용공고·직업훈련·청년정책을 추천하려면 5개 이상 외부 소스를 모아야 했고, 동기 처리는 느렸으며 핵심 필드인 신청 URL이 자주 비어 있었습니다.

액션

수집→정제→적재 ETL을 설계하고 정책 정제 단계를 asyncio + aiohttp 병렬 처리로 전환했습니다. URL 결측은 4단계 방어적 추출로 막았고, DB·벡터DB·임베딩·유사도 방식을 예산과 성능 기준으로 비교해 PostgreSQL + pgvector + KoSimCSE를 채택했습니다. 추천은 SQL 필터 → 벡터 재정렬 → 폴백 구조로 바꿨습니다.

결과

정제 시간 1,500초 → 726초(51.6% 단축), 정책 290건 전량 유효 URL, 추천 공고 4개 → 20개 이상. 부트캠프 최종 프로젝트 대상(1위), IITP 우수상.
